## Learned User Preferences

- Prefer real Google Sign-In on localhost over auth bypass; only enable bypass with `NEXT_PUBLIC_DEV_AUTH_BYPASS=true` when explicitly needed for UI-only testing.
- Expect fixes to be verified end-to-end (lint, tests, build, and browser flow) before considering them done.
- Keep Antigravity, Claude, and gstack skills available in Cursor via junction sync into `~/.cursor/skills/` (script: `~/.cursor/sync-skills.ps1`).
- In `/ordenes`, hide ID and Orden de trabajo from the main table; keep them in the detail/edit modal.
- In `/banos`, prefer operator search with datalist over a button grid; auto-fill date and entry time on capture (no manual date/time inputs).
- `/importar` ("Importar masivo") fue retirado por decisión del propietario; no recrear la ruta ni mostrarla en home/nav. Los helpers compartidos de `lib/importar.ts` permanecen porque Nueva Compra y Cotizaciones los reutilizan.
- `/almacen` is Entradas/Salidas only. The Reabastecimiento ROP tab was removed on 2026-07-24 because it ran on demo data in production; `lib/recompra-herramientas.ts` and the `reabastecimiento-rop` module id went with it. Don't recreate it without a real inventory source.
- SAT suggestions must be correct across every entry point (`/nueva-compra`, lote en `/ordenes`, `/reportes/contable`, `/claves-sat`), not only one module; prefer hybrid UX (one primary clave + 2–3 visible alternatives from the same local ranking).
- In `/proveedores`, keep USA and México markets separated; prefer one unified proveedores surface over many secondary panels; price intelligence should cover metales, plásticos, herramientas, and other insumos — not metals-only.
- In `/documentos-venta`, prefer a simplified UX (including chat) for sales users who are not strong with computers; label/search the customer PO as "órdenes de compra", not jargon-only "PO".
- In `/horas-extra`, only compras, contabilidad, and automatización personnel should be able to edit; diseño (and everyone else) is read-only. Enforced in both `lib/roles.ts` (`puedeEditarHorasExtra`) and `firestore.rules` (`puedeEditarHorasExtra()`) — keep them in sync. A dedicated `automatizacion` plantilla (`cotizaciones`, `requisiciones`, `horas-extra`, `notificaciones`) edits horas-extra same as admin/compras; `editaHorasExtra` remains only for one-off individual exceptions on other plantillas.

## Learned Workspace Facts

- Invoice extraction uses Gemini (`GEMINI_API_KEY` in `.env.local`), not Anthropic; override with `GEMINI_MODEL`. Defaults in `lib/extraer-ia.ts`: `gemini-3.7-flash` (normal), `gemini-3.1-pro-preview` (batch `calidad=alta`).
- Visible product name is **SMV Hub** (compras, diseño, operación del taller); repo and Firestore DB stay `compras-americanas` on Firebase project `smv-brain`.
- API routes `/api/extraer` and `/api/extraer-lote` require a valid Firebase ID token and an active `usuarios/{uid}` document through `lib/api-auth.ts`. `lib/authorized-emails.ts` now contains only the break-glass admin; keep that address synchronized with `firestore.rules`, `storage.rules`, and `functions/src/auth.ts`. `lib/usuarios-admin.ts` syncs Auth claims `smvHubActivo` and `smvHubModulos` (used by `storage.rules`) when access changes; claims refresh on the next sign-in/token refresh (≤1h). Backfill with `scripts/backfill-claims-usuarios.mjs`.
- Per line item: `empresa` and `destino` are the same concept (UI "Empresa / destino"), plus `cuentaCargo`, `requisitor`, and `ordenTrabajo` (optional for compras americanas); McMaster "Your Reference" maps to empresa + SO/cuenta cargo. Workshop tools (herramientas) default to empresa="SMV" and cuentaCargo="Stock" unless the invoice reference says otherwise; smart suggestions in `/nueva-compra` fill empty fields from history with IA-extracted values always taking priority — load via `listarOrdenesRecientes` (default 200), not a full `listarOrdenes()` scan. Duplicates = `numeroFactura` + `proveedor` (case-insensitive); blocks save in `/nueva-compra` and auto-deselects in CSV import. Invoice `total` includes shipping/freight when present; store `impuestos` as the dollar amount (US sales tax is state/local — 8.25% is Texas max, not universal). Avoid auto-`cargarTodas` / full-collection mounts on heavy screens; prefer ranged queries (`listarOrdenesEnRango`) and explicit "cargar historial" actions.
- Reports: when `fechaFactura` is null, `lib/reportes.ts` uses `creadoEn` for period filtering and the `dia` column so orders without invoice dates still appear. Prefer period-bounded fetches (then `filtrarPorRango`) over loading the full órdenes history. PDF export uses browser printing and Tailwind `print:` modifiers (no jspdf); hide Referencia when printing supervisor reports. Emailing uses `<ModalEnviarReporte>` with `mailto:` (preferred over SMTP/Resend when credentials are unavailable).
- SAT per item: `claveProdServ` + `satPendiente`; catalog (`data/sat/catalogo.json`, ~52k keys) is Spanish — translate English descriptions first. UI labels `pending-import` / Total 0 are client fallbacks when `/api/claves-sat` fails (often Turbopack SSR), not a missing catalog. Search/suggest is candidates-first via `lib/sat/buscar.ts` + `lib/sat/sugerir-clave.ts` (hybrid: primary clave + local alternativas; Gemini chooses among top-N candidates only). Anchor: “resorte(s) de compresión” / “Compression Spring” → `31161904`. Suggestions: glosario → `GEMINI_MODEL_SAT` (default `gemini-3.1-flash-lite`) in `lib/sat/gemini-sat.ts` (auto-falls back if set to retired `gemini-3.5-flash-lite`); ambiguous cases escalate to `GEMINI_MODEL_SAT_ESCALADO` (default `gemini-3.7-flash`). SMV areas → UNSPSC via `lib/sat/perfil-compras-smv.ts` (**taller** 23/27/30/31, **automatización** 26/32/39, **oficina** 14/41/45/55). Validated mappings persist to `sat_asignaciones` and load via `/api/sugerir-clave-sat` with `data/sat/mapeos-smv.json`.
- **Búsqueda semántica:** `busqueda_indice` contiene ítems de órdenes y proveedores, con embeddings de 768 dimensiones de `gemini-embedding-2-preview`; las reglas bloquean todo acceso cliente. `/api/busqueda-semantica` obtiene los resultados con Admin SDK, calcula coseno en servidor y filtra cada fuente por módulo (`ordenes`/`proveedores`) antes de leerla. El índice se sincroniza cada 24h mediante `syncBusquedaIndiceScheduled`, o manualmente sólo por super-admin, ambos con el secreto aislado `HUB_GEMINI_API_KEY`. El indexador hace full scan + hash para detectar bajas; conserva batches de **100** (no 400/500: los vectores de 768 dimensiones pueden superar el límite Firestore de 10 MiB por transacción). `embedding` está excluido de índices Firestore porque no se consulta con `findNearest`.
- **Hosting/security/build:** production stays on Firebase project `smv-brain` (Hosting/App Hosting); CI on `main` validates the app and selectively deploys only affected targets among `hosting`, Hub Functions, `firestore:rules`, and `storage`. Local dev targets `smv-brain-dev` (`.firebaserc` aliases). Data protection = Firebase Auth + active `usuarios` docs + module permissions + Firestore/Storage rules. App Check (reCAPTCHA v3) is initialized when configured, but Firestore/Storage rule enforcement has been paused since 2026-07-13 until console/domain validation is complete; follow `docs/infra/app-check-setup.md` before re-enabling it. Scheduled Firestore exports: `infra/firestore-backup/setup.sh`. **Shared project caveat:** `smv-brain` also hosts SMV-VISION (`triggerOdooSync`, `syncSuprajitOrders`) and Visual Factory functions. ## Cursor Cloud specific instructions

- **Runtime:** the app builds/tests/runs on Node 22 (VM default). `functions/` declares `engines.node: 20` but that only matters for Firebase deploy; local `functions` build (`cd functions && npm run build`) works on Node 22. `functions/` has its own `package.json`/`node_modules` — install it separately from the root.
- **Firebase config targets `smv-brain-dev`:** the injected `NEXT_PUBLIC_FIREBASE_*` secrets resolve to the dev project `smv-brain-dev` (auth-domain/bucket prefixes are `smv-brain-dev`). Next.js prefers real `process.env` over `.env.local`, so `npm run dev` connects to `smv-brain-dev` with **real** Google/email auth (no bypass needed). The money-path E2E (`e2e/camino-dinero.spec.ts`) writes only to `smv-brain-dev` — never repoint these secrets at production `smv-brain`.
- **Money-path E2E passes:** `npx playwright test --project=money-path` (login → capture with Gemini stubbed → order → report/currency → contable) passes here (needs `E2E_TEST_USER_PASSWORD`; Chrome preinstalled; run `npx playwright install ffmpeg` once for the `retain-on-failure` video). The E2E user `admin@smv-hub-e2e.local` already exists in `smv-brain-dev` (provisioned by CI / `scripts/crear-usuario-e2e.mjs`).
- **No admin service account:** `GOOGLE_APPLICATION_CREDENTIALS` is unset, so `firebase-admin` (`adminDb`) can't read/write Firestore server-side. Consequences: (1) every `/api/*` route calls `verificarUsuarioAutorizado` → `obtenerUsuarioAdmin` (an `adminDb` read), so API routes (`/api/extraer`, `/api/claves-sat`, etc.) return `401` even with a valid client token; (2) `scripts/crear-usuario-e2e.mjs` can't (re)create the E2E user; (3) the money-path E2E leaves one immutable `reportes_contables` lote in `smv-brain-dev` because its best-effort cleanup needs admin creds (this does NOT fail the test). A `smv-brain-dev` service account unblocks all three.
- **Gemini extraction works:** `GEMINI_API_KEY` is present and the core AI extractor (`lib/extraer-ia.ts` `extraerFactura`, model `gemini-3.7-flash`, REST + `ExtraccionInvoiceSchema`) runs successfully against a real invoice image (verified standalone via `tsx`). Not project-scoped to Firebase. In-app `/api/extraer` still needs the admin auth check above.
- **Firestore rules tests without cloud creds:** these run against the local emulator and are the best credential-free "does it actually work" check. `firebase emulators:exec` fails out-of-the-box because `firebase.json` has `hosting.source: "."`, which trips webframeworks detection. Work around it with a minimal temp config (no `hosting`) that points at the repo rules, e.g. `npx -y firebase-tools@latest emulators:exec --config /tmp/firebase.emulator.json --project smv-hub-reportes-integridad-rules "npm run test:emulator"` where the temp file contains only `{"firestore":{"rules":"/workspace/firestore.rules"},"emulators":{"firestore":{"port":8080},"ui":{"enabled":false},"singleProjectMode":true}}`. Java is preinstalled; `firebase-tools` is not (use `npx`).
- **Standard commands** live in `README.md` / `CLAUDE.md` / root `package.json`: `npm run dev` (Turbopack), `npm run build` (webpack + SSR bundle verifier — never drop `--webpack`), `npm run lint`, `npx tsc --noEmit`, `npm test`. `emulators:exec` also writes a `firestore-debug.log` at repo root — delete it after running so it doesn't dirty the tree.
